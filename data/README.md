# Data

## `synthetic/` (included, required)

**Synthetic data. Not market history.**

| file | content |
|---|---|
| `returns.csv` | 3,500 simulated daily observations |
| `metadata.json` | every generation parameter, the process definition, the initialisation, admissibility checks, the SHA-256 checksum and the generator details |

The data are generated by
`python scripts/generate_synthetic_data.py --config configs/synthetic_baseline.json`.
The process is GJR-GARCH(1,1,1) with standardised Student-t(8) shocks, seed 42,
with ω × 9 in two predefined stress regimes. The output is deterministic.
Regenerating it reproduces the same SHA-256
(`4df1b68d6be732704a7d30895e792a108409af89e244fb75fcdbf868c0845a6f`).

Schema of `returns.csv`:

| column | type | units / meaning |
|---|---|---|
| `date` | YYYY-MM-DD | synthetic Monday-to-Friday index from 2000-01-03. **Not an exchange calendar, no holidays.** |
| `return_pct` | float | simulated log return in percentage points (1.0 = 1%) |
| `true_vol_pct` | float | true conditional volatility σ_t of that day's return (pp), known at t−1 in the simulation |
| `stress_flag` | 0/1 | 1 inside a predefined stress regime |
| `regime` | text | `normal`, `stress_1` (indices 1,400–1,499) or `stress_2` (indices 2,500–2,599) |

Values are written with 10 decimals and `\n` line endings, so the checksum is
the same on every platform. The synthetic data were created for this project
and are covered by the project licence.

## `market/` (optional, not included)

See [`market/README.md`](market/README.md). No market data are distributed
with this project. The SPY example was downloaded and run locally; those
files stay local.

## Accepted input schemas (any CSV)

Loaded by `garch_fhs.data.load_returns_csv`. Column names are
case-insensitive.

- `date` + `adjusted_close`: returns are computed as
  `100·log(P_t/P_{t−1})`, and the first row is dropped.
- `date` + `return_pct`: returns are used as supplied, already in
  percentage-point log units.
- A file with both value columns, or neither, is rejected as ambiguous.
  Extra columns are kept.

## Missing-data and cleaning policy

- Unparseable dates, missing values and non-finite values are **rejected**,
  with an error naming the problem. Nothing is silently filled or dropped by
  the loader.
- Duplicate dates are **rejected**.
- Unsorted dates are **sorted** ascending, and the run metadata records that
  sorting happened.
- Prices must be strictly positive.
- The market download script drops rows with a missing adjusted close and
  records how many it dropped (it does not interpolate). Clean any other
  input before loading.
